# Directrices del proyecto FacilFactura

## Discutir antes de modificar

No se debe modificar nada — código de backend o frontend, esquema de base de datos, configuración de despliegue, etc. — sin antes discutir con el usuario cómo se va a abordar el cambio y obtener su acuerdo explícito sobre el enfoque. Esto aplica incluso a solicitudes que parecen simples, directas, o una continuación obvia de algo ya en curso: el usuario prefiere acordar el plan antes de que se empiece a escribir código, en vez de que se reaccione de inmediato a cada mensaje.

Antes de iniciar cualquier tarea de código:

1. Resumir el enfoque propuesto: qué se va a tocar, por qué, y alternativas relevantes si las hay.
2. Esperar la confirmación del usuario sobre ese enfoque.
3. Solo entonces proceder con la implementación.

Esto reemplaza, para este proyecto, el sesgo por defecto de actuar rápido sin pausar a confirmar.
